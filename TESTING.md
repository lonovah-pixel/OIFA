# Проверка SITE-VEIL

Три уровня проверки, и они **не равнозначны**:

| Уровень | Что подтверждает | Чего не подтверждает |
|---|---|---|
| **Статическая** — glualint 1.30.0 | синтаксис GLua, неиспользуемые переменные, затенение, глубина вложенности, стиль | поведение |
| **Автоматическая без игры** — LuaJIT + имитация API + SQLite | серверная логика режима на настоящем коде: права, состояния, переходы, лимиты, БД, сеть; загрузка клиентских модулей и выполнение HUD/вкладок/обработчиков без ошибок Lua | движок: физика, трассировки, отрисовка, VGUI, сеть между клиентом и сервером, настоящий DarkRP, производительность |
| **В игре** — SRCDS + клиенты | всё остальное | — |

**В игре режим не проверялся**: в среде разработки нет Garry's Mod и SRCDS (Steam CDN недоступен). Планы ручной проверки ниже нужно выполнить до запуска сервера для игроков.

## 1. Автоматические проверки

```
tools/install_glualint.sh   # один раз
tools/check.sh              # линтер + все тесты
tools/check.sh lint         # только линтер
tools/check.sh test         # только тесты
python3 -I tests/harness/runner.py tests/server/test_stage4.lua   # один файл
```

Требования: `python3`, пакет `lupa` (LuaJIT), `sqlite3` из стандартной библиотеки Python. Любой вывод glualint считается ошибкой.

### Как устроено

- `tests/harness/gmod_mock.lua` — подмножество API сервера GMod и DarkRP: хуки (детерминированный порядок), таймеры и время (`MOCK.advance`), `net` (запись отправленного, имитация клиентских запросов `MOCK.rpc`), `sql` поверх настоящего SQLite в памяти, игроки и сущности, урон (уменьшает здоровье и убивает), векторы и углы, трассировки (по умолчанию свободны, тест может подменить `MOCK.traceFn`/`MOCK.hullFn`).
- `tests/harness/boot.lua` — тот же порядок загрузки, что `init.lua`; помощники `TEST`, `expect`, `eq`, `contains`, `makeStaff`, `uniqueName`.
- `tests/harness/client_stubs.lua` — клиентский режим: панели VGUI, принимающие любые вызовы, пустая отрисовка, локальный игрок. Неизвестные глобальные имена **не** подменяются, чтобы отсутствующие API давали ошибку.
- `tests/harness/runner.py` — запускает каждый файл в отдельном экземпляре LuaJIT и SQLite; при полном прогоне записывает образцы push-сообщений сервера в `tests/.fixtures/pushes.json`, которые клиентский тест прогоняет через клиентские обработчики.

## 2. Подготовка к ручной проверке

1. Сервер по [README.md](README.md), карта `gm_construct` (есть в любой установке GMod), `sv_rng_seed 12345` для воспроизводимости, 2–4 клиента (можно `-multirun`).
2. Один клиент — суперадминистратор. Разметьте минимальную карту ([ADMIN_GUIDE.md](ADMIN_GUIDE.md), раздел 3) и сохраните.
3. В консоли сервера после загрузки не должно быть строк `[SITE-VEIL]` с ошибками; вкладка «Состояние сервера» — «Интеграция DarkRP: проверена».

Для каждого пункта: шаги → ожидаемый результат. Расхождение — дефект; записывайте карту, зерно и время.

## 3. Планы ручной проверки

### 3.1 Основа и DarkRP
1. Подключиться → экран персонажей, игрок невидим и неуязвим. Создать персонажа «Иван Петров», Класс D → появление на точке группы `classd`, HUD SITE-VEIL, никакого HUD DarkRP.
2. F4 / F1 / F2 → вкладки SITE-VEIL, не меню DarkRP.
3. В чат: `/job`, `/buy`, `/give 100`, `/dropmoney`, `/advert` → команды не существуют. В консоль `rp_citizen` → ничего.
4. `/me машет рукой` рядом и в 400 ед. → видно только рядом.

### 3.2 Доступ и двери
1. Настроить дверь с допуском 2. Класс D → «Доступ запрещён», запись в журнале (`sv_doorlog` у охраны). Офицер СБ (допуск 2) → открыто.
2. Отключить узел питания сектора (урон по узлу) → дверь ведёт себя по «без питания»; инженер открывает вручную (ПКМ набором инструментов).
3. Выдать временный пропуск, дождаться истечения → пропуск перестаёт работать.

### 3.3 Связь и голос
1. Два игрока в разных концах карты: голос без рации не слышен; с рацией на общем канале при `+sv_radio` — слышен.
2. Повредить узел связи сектора → сообщения `/r` искажаются у слушателей в других секторах.

### 3.4 Инфраструктура и режимы
1. Генератор до 40 % → секторы с низким приоритетом переходят на резерв, мигает свет; топливо расходуется.
2. Начальник СБ объявляет локальную тревогу → баннер и звук; повторное объявление раньше 60 с — отказ с причиной.
3. Побег SCP (см. 3.7) → автоматически «Нарушение содержания»; «Восстановление» нельзя объявить, пока объект вне камеры.

### 3.5 Медицина
1. Выстрел 150 урона по ноге → недееспособен, ползает, таймер в HUD. Медик: жгут → «стабилен»; врач: стимулятор → встаёт с 30 HP.
2. Не помогать → смерть по таймеру; `/giveup` раньше 20 с — отказ.
3. Выйти из игры в недееспособном состоянии → вещи выпадают в мешке.

### 3.6 Охрана
1. `/surrender` → охранник надевает наручники мгновенно; через 8 минут снимаются автоматически, повторно сразу нельзя.
2. Обыск → окно с предметами; изъять заточку → запись в журнале изъятий терминала СБ. Удостоверение не изымается.
3. Задержание без основания — отказ; с основанием на 60 минут — ограничено званием; переподключение — задержание продолжается.

### 3.7 SCP
1. **173**: игрок-173 в камере. Охранник смотрит на 173 → 173 заморожен (надпись «ЗА ВАМИ НАБЛЮДАЮТ»); закрыть объект стеной/дверью → разморожен. Моргание по шкале → короткое окно движения. Выключить свет в секторе → наблюдение работает только вблизи или с фонарём. Повторное содержание: два наблюдателя + МОГ 12 с.
2. **106**: касание → жертва в карманном измерении (или затемнение без зоны кармана); выход через точку `pocket_exit`; без выхода — выброс по таймеру. Фазирование через дверь в стену (место занято) → отказ без телепорта.
3. **049**: касание без костюма → симптомы; через 4 минуты вторая стадия (замедление). «Лечение» недееспособного → он появляется как SCP-049-2 на месте тела; через 7 минут или при гибели — возвращается к своему персонажу, на месте гибели — образец тканей.
4. **096**: посмотреть в лицо → цель (надпись на экране), 6 с плача, ярость; другие игроки не атакуются; убить цель → успокоение → истощение → покой. Мешок на истощённого → возврат в камеру.
5. Без игрока за SCP: нарушить условия (обесточить камеру) → стадии ухудшаются, на «побеге» через минуту — тревога, но объект не выходит.

### 3.8 Исследования
1. Исследователь создаёт «Калибровку AO-3127», держит объект → «Начать», шаги, результат в окне и в журнале. `sv_research_replay <id>` в консоли сервера → тот же исход.
2. Опасный протокол → «Начать» заблокировано до согласования; согласовать собственный — отказ.
3. Прервать критический шаг (выйти из зоны) → аварийное прекращение, возможен инцидент.

### 3.9 Улики и дела
1. Ранить игрока → следователь: ЛКМ набором криминалиста → метка «Следы крови», возраст «недавно»; ПКМ → пакет с уликой.
2. Терминал СБ → первичный анализ (подразделение, окно времени), лабораторный с набором датчиков (имя пострадавшего).
3. Завести дело, приобщить улику, закрыть с заключением.

### 3.10 Директор, скрытые задания, подкрепление
1. Админ-панель → «Запустить» «Перегрев силового узла» при инженере на смене → предупреждение, затем неисправность и задача в HUD; ремонт → «выполнено». Без инженеров на сервере кнопка заблокирована «некому решить».
2. Вкладка «Личное» → согласие. При онлайне ≥ 8 и после 5 минут в должности предложение приходит в одном из раундов (каждые 5 минут, шанс 35 %; с `sv_rng_seed` — воспроизводимо). Отказ — без последствий, следующее предложение не раньше чем через 15 минут.
3. Персонаж МОГ встаёт в очередь; при «Нарушении содержания» начальник СБ вызывает МОГ → через 60 с боец появляется на точке подкрепления.

### 3.11 Администрирование
1. Дежурство → физган, noclip, редактор карты; выход — инструменты убраны.
2. Панель: выдать допуск МОГ игроку → он может создать персонажа МОГ; отозвать → не может.
3. `@помогите` от игрока → обращение в панели; ответ виден игроку.

### 3.12 Производительность
На 30+ игроках: `sv_perf` каждые 5 минут. Ориентиры: тик наблюдения 173 < 0,5 мс, директор < 0,2 мс, синхронизация < 1 мс; число следов не превышает 250, предметов в мире — лимита инвентаря. Значения на живом сервере не измерялись.
