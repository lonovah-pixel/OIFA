# Руководство администратора SITE-VEIL

## 1. Права (CAMI)

SITE-VEIL регистрирует привилегии через CAMI, поэтому их выдаёт любой админ-мод (FAdmin из DarkRP, ULX, SAM …). Проверка выполняется на сервере для каждого действия.

| Привилегия | По умолчанию | Что даёт |
|---|---|---|
| `SiteVeil_Admin` | admin | режим дежурства, панель администратора (игроки, обращения, журнал), директор, скрытые задания |
| `SiteVeil_Whitelist` | admin | выдача и отзыв допусков (whitelist) к подразделениям и ролям |
| `SiteVeil_MapConfig` | superadmin | редактор карты |
| `SiteVeil_Diagnostics` | admin | отчёт производительности |

## 2. Режим дежурства

`/adminduty` или F4 → «Администрирование» → «Заступить на дежурство». На дежурстве: бессмертие, noclip, физган и тулган, полный доступ к дверям и терминалам, возможность прекращать эксперименты и вызывать подкрепление, инструмент «Настройка карты» (для суперадминистраторов). Вне дежурства администратор играет обычной ролью персонажа без привилегий. Вход и выход из дежурства видят другие администраторы; всё пишется в журнал аудита.

## 3. Разметка карты

Режим не привязан к карте. Без разметки работает **автоматический макет**: один сектор на всю карту и точки, построенные по точкам появления карты с проверкой трассировками; админ-панель показывает предупреждение. Для полноценной игры карту нужно разметить.

Разметка хранится в `garrysmod/data/siteveil/maps/<карта>.json`. Порядок загрузки: файл из `data` → встроенный `gamemode/mapcfg/<карта>.lua` (в поставке отсутствуют: координаты не выдумываются) → автоматический макет.

### Инструмент

1. Заступите на дежурство (суперадминистратор) — выдаётся «Настройка карты».
2. ЛКМ/ПКМ — угол 1 и угол 2 объёма по взгляду; R — окно редактора. Пока инструмент в руках, зоны, точки и двери рисуются в мире.
3. Все позиции берутся **сервером** из вашей позиции или взгляда; клиент координаты не присылает.
4. «Сохранить» записывает файл и показывает число ошибок/предупреждений; «Проверить» — только проверка; «Перечитать» — загрузить с диска; «Пересоздать сущности» — терминалы, шкафы, узлы, панели; «Автомакет» — построить автоматический макет (не сохраняется); «Экспорт» — Lua-файл `data/siteveil/export/<карта>.lua.txt`, который можно положить в `gamemode/mapcfg/<карта>.lua` и распространять вместе с режимом.

### Зоны (объёмы из одного или нескольких параллелепипедов)

| Тип | Параметры | Назначение |
|---|---|---|
| `sector` | `priority` (0–3), `demand` (потребление) | сектор комплекса: питание, тревоги, блокировки — **обязателен хотя бы один** |
| `cell` | `scp` (id объекта) | камера содержания; без неё используется окружность вокруг точки появления SCP |
| `evac` | — | шлюз эвакуации |
| `detention` | — | камера задержания (задержать можно только в ней, если такие зоны есть) |
| `pocket` | — | карманное измерение SCP-106 (без него — имитация с гарантированным выходом) |
| `lure` | — | камера приманки SCP-106 |
| `testchamber` | — | испытательная камера рядом с исследовательским терминалом |
| `safe` | — | безопасная зона: атакующие способности SCP запрещены |

### Точки

| Тип | Параметры | Сущность |
|---|---|---|
| `spawn` | `group` = id роли, подразделения или `any` | — |
| `checkpoint` | `name` | — (посты обхода, места событий директора) |
| `terminal` | `terminal` = `research` / `infrastructure` / `security` / `logistics` / `records` / `medical`; необязательно `clearance`, `tags` | `sv_terminal` |
| `node` | `subsystem` = `generator` / `power` / `comms` / `ventilation` / `surveillance` / `security`; `sector`; `name` | `sv_infra_node` |
| `locker` | `locker` = `armory` / `medical` / `engineering` / `science` / `general` | `sv_locker` |
| `panel` | `scp` | `sv_containment_panel` |
| `logistics` | `name` | — (точка доставки поставок) |
| `reinforcement` | `group` = `mtf` / `chaos` | — |
| `pocket_exit` | — | выход внутри карманного измерения |
| `emergence` | — | точка выхода SCP-106 и выброса из кармана |
| `stash` | — | тайник для скрытых заданий (без тайников такие задания не предлагаются) |
| `tesla` *(аддон tesla)* | `name`, `sector`, `radius` | `sv_tesla_gate` |
| `camera` *(аддон cctv)* | `name`, `sector`; направление — угол точки («Добавить по взгляду» ставит точку туда, куда вы смотрите, угол — по вашему взгляду) | `sv_cctv_camera` |

Терминалы аддонов: `terminal=intercom` (интерком), `terminal=cctv` (пост видеонаблюдения). Типы появляются в редакторе, только когда соответствующий аддон установлен; см. [ADDONS.md](ADDONS.md).

### Двери

Посмотрите на дверь или кнопку карты, задайте название, допуск (0–5), политику (по карте / свободно / закрыто), поведение без питания (заперта / открыта), зоны доступа (`security,armory`) и сектор, затем «Настроить дверь по взгляду». Двери без настройки работают как обычные двери карты.

### Проверка

Проверка ловит: отсутствие секторов, повторяющиеся идентификаторы, неизвестные типы и параметры, пустые или вывернутые объёмы, точки вне мира, точки появления, где игрок застрянет, неизвестные группы, сектора, подсистемы, терминалы, несуществующие двери и допуск вне диапазона, SCP без камеры. Ошибки и предупреждения видны в редакторе и во вкладке «Состояние сервера».

### Минимальная рабочая разметка

Сектор (или несколько), точки появления для подразделений, по одному узлу `generator` и `power`, терминалы `research` и `security`, шкафы `armory` и `medical`, камеры и панели для используемых SCP, зона `detention`, одна-две точки `logistics` и `checkpoint`.

## 4. Допуски (whitelist)

F4 → «Администрирование» → «Панель администратора» → «Игроки» → «Допуски». Выдаются на подразделение (`division`) или конкретную роль (`role`), с основанием. Требуют допуска: МОГ, Повстанцы Хаоса, руководящие роли (руководители отделов, директор), игровые SCP. Все выдачи и отзывы — в журнале аудита.

## 5. Обращения игроков

Игроки пишут `@текст` или `/report текст`. Обращения видны в панели («Обращения»): взять, ответить, закрыть. Если администраторов нет в сети, обращение сохраняется до перезапуска сервера.

## 6. Журнал аудита

«Панель администратора» → «Журнал аудита»: фильтр по категории (`character`, `access`, `security`, `medical`, `scp`, `research`, `evidence`, `director`, `hidden`, `reinforcements`, `admin`, `net`, …), SteamID64 и тексту. Это точные записи (кто, кому, где, когда) — игроки их не видят: в игре им доступны только округлённые журналы и результаты экспертиз ограниченной точности.

## 7. Директор напряжения

Блок «Директор напряжения» во вкладке администрирования: включение/выключение, текущее напряжение, время до следующего решения, список событий с причинами блокировки, запуск события вручную, снятие активного события, журнал. Отключение отдельного события сохраняется в настройках сервера. Консольная переменная `sv_director 0` выключает директора полностью.

## 8. Скрытые задания

Включение/выключение — в той же вкладке или `sv_hidden_tasks 0`. При выключении активные задания снимаются без последствий для игроков.

## 9. Переменные и команды

| Переменная / команда | Назначение |
|---|---|
| `sv_director 0/1` | директор напряжения |
| `siteveil_addons_disabled "id,id"` | не загружать перечисленные аддоны SITE-VEIL (перезапуск) |
| `sv_hidden_tasks 0/1` | скрытые задания |
| `sv_rng_seed <число>` | фиксированное зерно для воспроизводимых проверок |
| `sv_perf` | отчёт производительности в консоль (время тиков, счётчики, реестры) |
| `sv_research_replay <id>` | повторить бросок исхода эксперимента по сохранённым зерну и весам (суперадмин/консоль) |
| `sv_cards` (клиент) | окно управления удостоверениями (выдача пропусков, отзыв — по правам роли) |
| `sv_doorlog` (клиент) | журнал доступа двери или терминала, на которые вы смотрите (по правам роли) |
| `sv_interact`, `sv_experiment` (клиент) | меню взаимодействия с игроком по взгляду; окно текущего эксперимента |

## 10. Неполадки

- **Вкладка «Состояние сервера» показывает ошибки загрузки** — модуль не загрузился из-за зависимости или ошибки Lua; подробности в консоли сервера.
- **«Интеграция DarkRP: есть проблемы»** — `sv_verify` нашёл незакрытую команду/профессию/модуль DarkRP (обычно после обновления DarkRP или установки аддона). См. [DARKRP_CHANGES.md](DARKRP_CHANGES.md).
- **«База данных недоступна»** — создание и сохранение персонажей отключено, чтобы не потерять данные; проверьте права на `garrysmod/sv.db`.
- **Игроки застревают при появлении** — запустите «Проверить» в редакторе карты: точки, где игрок не помещается, отмечены предупреждением.
